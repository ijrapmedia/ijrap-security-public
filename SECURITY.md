# Security Policy

## Project Context
**IJRAP Security** is an open-source cryptographic sealing and forensic integrity engine designed for investigative journalism and field data collection. Because our tool protects sensitive evidence, we treat all security reports with the highest priority.

## Supported Versions
Only the latest active release receives security updates and cryptographic patches.

| Version | Supported          |
| ------- | ------------------ |
| 0.x     | :white_check_mark: |
| 1.x     | :white_check_mark: |

## Reporting a Vulnerability
**Please do not report security vulnerabilities through public GitHub issues.**

If you discover a vulnerability in IJRAP Security (such as a cryptographic flaw, hash collision weakness, or local storage exposure), please report it privately using one of the following methods:

1. **GitHub Private Vulnerability Reporting (Recommended):** Go to the **Security** tab of this repository, click **Advisories**, and select **Report a vulnerability**.
2. **Direct Email:** Send a detailed report to **imoadze1@gmail.com**.

### What to include in your report
To help us reproduce and fix the issue quickly, please include:
* A clear description of the vulnerability and its potential impact.
* Step-by-step instructions to reproduce the issue.
* The version of IJRAP Security and the operating system (Linux, Windows, Android/Kivy) affected.

## Response Timeline
* **Acknowledgment:** We will acknowledge receipt of your report within **48 to 72 hours**.
* **Updates:** We will keep you informed of our progress toward a fix at least once every **7 days**.
* **Disclosure:** We follow a coordinated disclosure process. Once a patch is ready and released, we will publicly credit you for the discovery (unless you prefer to remain anonymous).
